This guide provides step-by-step instructions to install and run `K6`, a powerful load testing tool, to test your Spring Boot applications.

1. Standalone Installation.

    1. Import the GPG key:
        ```bash
        curl -s https://dl.k6.io/key.gpg | gpg --dearmor | sudo tee /usr/share/keyrings/k6-archive-keyring.gpg
        ```

    1. Add the `K6` repository:
        ```bash
        echo "deb [arch=amd64 signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
        ```

    1. Update the package list and install `K6`:
        ```bash
        sudo apt update && sudo apt install k6
        ```

1. Create and initialize a new `K6` script:
    ```bash
    k6 new
    ```

1. Run the test:

    1. Normal execution:
        ```bash
        k6 run script.js
        ```

    1. Run a load test with multiple virtual users and a longer duration:
        ```bash
        k6 run --vus 10 --duration 30s script.js
        ```

    1. Pass environment variables to your testing script:
        ```bash
        K6_VUS=10 K6_DURATION=10s k6 run script.js

        k6 run -e MY_HOSTNAME=http://localhost:8080/api/v1/users script.js
        ```

1. Test one of our Spring Boot Applications.

    Start `samples/08-restapi` first (`mvn spring-boot:run` from that folder). The scripts call `http://localhost:8080/api/v1/users`.

    HTTP Basic scripts need `samples/18-security` instead of the REST sample.

    `11-basic-authentication.js` sends Basic credentials on each request.
    `12-setup-auth.js` uses k6 `setup()` to build an `Authorization` header once, then the VUs reuse it.

    ```bash
    cd samples/20-k6
    k6 run 02-lifecycle-sample.js
    k6 run 03-simple-get.js
    k6 run 04-stages.js
    k6 run 05-checks.js
    k6 run 06-thresholds.js
    k6 run 07-scenarios.js
    k6 run -e MY_HOSTNAME=http://localhost:8080/api/v1/users 08-environment-variables.js
    k6 run -e SECURITY_USER_USERNAME=user -e SECURITY_USER_PASSWORD=change-me 11-basic-authentication.js
    k6 run -e SECURITY_USER_USERNAME=user -e SECURITY_USER_PASSWORD=change-me 12-setup-auth.js
    ```

    `11-basic-authentication.js` also shows credentials in the URL. Prefer
    `12-setup-auth.js` (`setup()` + `Authorization` header) for real scripts.

1. App-adjacent scripts.

    Real applications keep k6 scripts in `src/test/k6/`, not in a sibling catalog
    folder. The virtual-threads sample does that. Start that app, then:

    ```bash
    cd samples/16-virtual-threads/src/test/k6
    k6 run 01-block-3.js
    k6 run 02-block-3-report.js
    ```

    Override the target with `BASE_URL` when the app is not on
    `http://localhost:8080`. HTML reports write to `output/` (gitignored). Do not
    commit generated reports, and do not copy them into Thymeleaf `templates/`.
