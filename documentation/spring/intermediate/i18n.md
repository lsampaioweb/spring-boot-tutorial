# i18n

Keep user-facing text in message bundles and resolve them by locale.

Working samples:

- [`samples/06-i18n`](../../../samples/06-i18n) — [`README`](../../../samples/06-i18n/README.md) — `MessageSource` only (no web)
- [`samples/08-restapi`](../../../samples/08-restapi) — HTTP locale on REST (`Accept-Language`)

Later samples reuse the same bundle layout under `src/main/resources/i18n`.

## Before you start

- Previous: [Lombok](../basic/lombok.md) — `samples/05-lombok`
- Java 25, Maven 3.9+
- Time: ~15 minutes for `06-i18n`

## Why this exists

Hard-coded strings do not scale across languages or environments. Spring’s
`MessageSource` loads property files; REST samples later pick the locale from
the request. Start with a non-web runner so the lookup is obvious in the logs.

## What you will see

With `development` on `06-i18n`:

- `English: Hello, Welcome to our site!`
- `English with name: Hello, Luciano!`
- `Portuguese: Olá, seja bem-vindo ao nosso site!`
- `Portuguese with name: Olá, Luciano!`

## Run

```bash
cd samples/06-i18n
mvn spring-boot:run -Dspring-boot.run.profiles=development
```

Base config:

```yml
spring:
  messages:
    basename: "i18n/messages"
    encoding: "UTF-8"
    default-locale: "en"
    fallback-to-system-locale: false
```

Bundles live at `src/main/resources/i18n/messages.properties` and
`messages_pt_BR.properties` (`greeting`, `greeting.message`).

## Try it

Watch the console after startup (no HTTP port in `06-i18n`).

Expected INFO lines matching the English and Portuguese greetings above.

After you reach REST (`08-restapi`), send `Accept-Language: pt-BR` on requests
that surface localized messages. Thymeleaf later uses `#{...}` / `?lang=` on HTML.

## How the sample is shaped

| File / class | Role |
| --- | --- |
| `I18nApplication` | `CommandLineRunner` + `MessageSource` lookups |
| `i18n/messages*.properties` | EN / pt-BR keys |
| `I18nConsistencyTest` | Same keys and placeholder arity across locales |

Optional HTTP shape (in `08-restapi`): `AcceptHeaderLocaleResolver` +
`LocaleContextHolder.getLocale()` when resolving messages in request code.
