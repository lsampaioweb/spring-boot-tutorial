Internationalization (`i18n`) lets a Spring Boot application keep user-facing text out of Java code. This tutorial teaches it in two steps.

Working samples:

- `samples/06-i18n` — `MessageSource` only. No web, REST, or Actuator.
- `samples/08-restapi` — HTTP locale from `Accept-Language` (and a `lang` query parameter) on the first REST API.

Later samples reuse the same bundles and `MessageSource` lookup.

## 1. MessageSource without HTTP

Start here. Resolve messages by passing a `Locale` to `MessageSource`. That is enough to learn keys, placeholders, and locale files.

1. Point Spring at the message bundles.

    `application.yml`:

    ```yml
    spring:
      messages:
        basename: "i18n/messages"
        encoding: "UTF-8"
        default-locale: "en"
        fallback-to-system-locale: false
    ```

1. Add one file per locale under `src/main/resources/i18n`.

    `messages.properties`:

    ```properties
    greeting=Hello, Welcome to our site!
    greeting.message=Hello, {0}!
    ```

    `messages_pt_BR.properties`:

    ```properties
    greeting=Olá, seja bem-vindo ao nosso site!
    greeting.message=Olá, {0}!
    ```

1. Look up messages in Java.

    The `06-i18n` sample is a `CommandLineRunner` that logs the same keys in English and `pt-BR`:

    ```java
    log.info("English: {}", messageSource.getMessage("greeting", null, Locale.ENGLISH));
    log.info("Portuguese: {}",
        messageSource.getMessage("greeting", null, Locale.forLanguageTag("pt-BR")));
    ```

    Run it with `mvn spring-boot:run` from `samples/06-i18n` and read the log lines.

## 2. HTTP locale on REST

After REST exists (`samples/08-restapi`), resolve the locale from the request and keep using `MessageSource`.

1. Register a `LocaleResolver`.

    Use Spring's `AcceptHeaderLocaleResolver` with a default locale and the locales you ship bundles for:

    ```java
    @Configuration
    class I18nLocaleResolverConfig {

      @Bean
      LocaleResolver localeResolver() {
        AcceptHeaderLocaleResolver resolver = new AcceptHeaderLocaleResolver();
        resolver.setDefaultLocale(Locale.ENGLISH);
        resolver.setSupportedLocales(List.of(Locale.ENGLISH, Locale.forLanguageTag("pt-BR")));

        return resolver;
      }
    }
    ```

    Thymeleaf later adds `?lang=` links. That is a query-parameter override on HTML pages, not part of this first REST sample.

1. Read the active locale in request code.

    ```java
    messageSource.getMessage(
        "error.sort.property.invalid",
        new Object[] { property },
        LocaleContextHolder.getLocale());
    ```

    Bean Validation messages use the same bundles with `{error.validation.*}` keys.

1. Test locale selection.

    Send `Accept-Language: pt-BR` on REST requests. The HTML sample uses `?lang=` links.

## 3. HTML pages

Thymeleaf (`samples/13-thymeleaf`) uses the same message keys in templates:

```html
<h1 th:text="#{greeting}">Greeting</h1>
```
